# Portrait Treatment Brief

> Status: portrait-only companion spec dla hero w `.design-brief.md`.
> Last updated: 2026-06-22
>
> Ten plik opisuje tylko obraz, frame, overlay i lokalny glow.
> Paleta strony, typography, CTA hierarchy i section rules pozostaja w `.design-brief.md`.

## 1. Zakres i invariants

- Hero ma jeden aktywny visual direction: real portrait w ramce 3:4.
- Nie utrzymujemy drugiego aktywnego wariantu hero obok tego dokumentu.
- Glow pozostaje lokalny dla frame portretu.
- Page-level halo za calym hero nie nalezy do aktualnej specyfikacji.

## 2. Image treatment

```css
.portrait-img {
  filter: grayscale(0.6) contrast(1.12) brightness(0.88) sepia(0.15) saturate(0.7);
  transition: filter 400ms ease-out;
}

.portrait-img:hover {
  filter: grayscale(0.3) contrast(1.08) brightness(0.92) sepia(0.08) saturate(0.9);
}

@media (prefers-reduced-motion: reduce) {
  .portrait-img {
    transition: none;
  }
}
```

- Cel: schlodzic kadr, ograniczyc cieplo tla i zachowac naturalny odcien skory.
- Hover jest subtelnym reveal, nie osobnym efektem art direction.

## 3. Frame i overlay

```css
.portrait-container {
  border-radius: 16px;
  overflow: hidden;
  position: relative;
  background: var(--color-bg-card);
  border: 1px solid var(--color-border);
  box-shadow:
    inset 0 0 120px rgba(0, 211, 242, 0.14),
    0 8px 32px rgba(0, 0, 0, 0.4);
}

.portrait-container::after {
  content: '';
  position: absolute;
  inset: 0;
  border-radius: inherit;
  pointer-events: none;
  z-index: 2;
  background: radial-gradient(
    ellipse at 50% 40%,
    transparent 45%,
    rgba(0, 0, 0, 0.3) 85%,
    rgba(0, 0, 0, 0.5) 100%
  );
}
```

- `--color-bg-card` daje bezpieczne tlo przed zaladowaniem obrazu.
- Inset glow korzysta z aktualnego brand primary-muted.
- Vignette sciaga uwage do twarzy i pomaga wygasic krawedzie kadru.

## 4. Hover state

```css
.portrait-container:hover .portrait-img {
  filter: grayscale(0.3) contrast(1.08) brightness(0.92) sepia(0.08) saturate(0.9);
  transform: scale(1.02);
}

.portrait-container:hover {
  border-color: var(--color-border-hover);
  box-shadow:
    inset 0 0 120px rgba(0, 211, 242, 0.18),
    0 8px 32px rgba(0, 0, 0, 0.4);
}
```

- Reveal idzie przez obraz, nie przez dodatkowe dekoracje wokol hero.
- Vignette nie zmienia sie na hover.

## 5. Responsive sizing

| Breakpoint | Kontener | Image behavior |
|---|---|---|
| Mobile `<640px` | `w-72 aspect-[3/4]` | `object-fit: cover; object-position: top center;` |
| `sm` | `w-80 aspect-[3/4]` | j.w. |
| `lg` | `w-[380px] aspect-[3/4]` | j.w. |

- Portret ma zachowac staly frame proportion bez przeskokow layoutu.
- Twarz musi zostac widoczna na mobile i desktop.

## 6. Badge i fallback

- Badge "Available for work" zostaje nad frame z `role="status"`.
- Status dot korzysta z `--color-success`.
- Initials fallback moze pojawic sie tylko po errorze ladowania assetu.
- Fallback initials nie sa pelnoprawnym wariantem hero.

## 7. Performance notes

- Hero portrait jest LCP element.
- `loading="eager"` i `fetchpriority="high"` pozostaja wymagane.
- Preferowany pipeline: `astro:assets` responsive outputs.
- Zachowac zgodnosc z preloadem w `Layout.astro`.

## 8. HTML structure

```astro
<div class="portrait-container w-72 sm:w-80 lg:w-[380px] aspect-[3/4] rounded-2xl overflow-hidden relative">
  <img
    src="/portrait.jpg"
    alt="Krzysztof Kocot -- Full-Stack Developer"
    class="portrait-img w-full h-full object-cover object-top"
    loading="eager"
    decoding="async"
    fetchpriority="high"
  />
</div>
```

- Overlay dolny i lokalny glow sa dekoracyjne.
- Relacja master/companion zostaje prosta: `.design-brief.md` definiuje hero direction, ten plik definiuje treatment obrazu.
