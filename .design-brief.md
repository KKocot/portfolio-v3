## 2. Color Palette

### Decyzja: Kierunek A -- Dark Navy + Warm Gold

**Dlaczego A, nie B/C/D:**

- Kierunek B (light theme) -- odrzucony. User zadeklarowal dark-only, a light editorial vibe nie komunikuje "technologia" polskim SMB. Wlasciciele firm w Polsce kojarzla jasne strony z tanimi template'ami WordPress.
- Kierunek C (refined dark + inny akcent) -- bliski, ale brak wyraznej osobowosci. Cyan/violet/amber na czarnym = kazde inne portfolio developera.
- Kierunek D -- brak lepszej alternatywy niz A.
- **Kierunek A wygrywa** bo: (1) navy zamiast pure black jest ciezszy, bardziej premium, mniej "coder aesthetic"; (2) warm gold/amber komunikuje jakosc i biznesowa powaznie (konotacja: luxury, trust, premium service); (3) kombinacja navy+gold jest rzadka w portfoliach developerow wiec wyroznia; (4) dla SMB decision makera (nie-technicznego) kojarzy sie z profesjonalna agencja, nie z jednym gosciem w bluzie.

## 3. Typography

### Font Selection

**Display (h1, h2):** `Space Grotesk` (Google Fonts, waga 500-700)
- Dlaczego: geometric sans-serif z personality -- szerokie proporcje, wyrazisty charakter, ale nie serif (serif w PL kojarzy sie z kancelaria prawna, nie tech). Space Grotesk komunikuje "nowoczesnosc + solidnosc" -- idealny middle ground miedzy Playfair (za editorial) a Inter (za generyczny na headlines).
- Dlaczego nie Instrument Serif: serif na dark bg z gold akcentem to risk "old money" vibes zamiast "modern tech". SMB w PL nie kupuje old money, kupuje "nowoczesny i profesjonalny".
- Dlaczego nie Syne/Fraunces: zbyt artystyczne, nieczytelne w polskich znakach diakrytycznych.

**Body:** `Inter` (zostaje)
- Dlaczego: doskonaly do body, testowany, ma wszystkie polskie znaki, doskonaly na ekranach. Nie ma powodu do zmiany -- zmiana body fontu to risk regresji czytelnosci.

### Font Loading

```html
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600&family=Space+Grotesk:wght@500;600;700&display=swap" rel="stylesheet" />
```

Uwaga: Inter wagi 300 (light) usuwamy -- nie jest uzywana w stronie, waga 700 (bold) tez nie jest potrzebna z Space Grotesk w headlinesach. Redukcja: 5 weights -> 6 weights (3+3), ale 2 font families.

## 4. Motion & Micro-interactions

**Zasada nadrzedna:** CSS-only, zero JS animation libraries. Wszystkie animacje musza miec `prefers-reduced-motion` fallback.

### 4.1 Hero Entrance (page load)

```css
/* Stagger: visual -> tag -> h1 -> description -> CTAs -> scroll indicator */
/* Kazdy element: fade-up, 0px -> 0px z opacity 0 -> 1 */
.hero-animate {
  opacity: 0;
  transform: translateY(24px);
  animation: heroFadeUp 0.7s cubic-bezier(0.16, 1, 0.3, 1) forwards;
}

/* Stagger delays */
.hero-delay-0 { animation-delay: 0.1s; }   /* portrait/visual */
.hero-delay-1 { animation-delay: 0.2s; }   /* tag */
.hero-delay-2 { animation-delay: 0.35s; }  /* h1 */
.hero-delay-3 { animation-delay: 0.5s; }   /* description */
.hero-delay-4 { animation-delay: 0.65s; }  /* CTAs */
.hero-delay-5 { animation-delay: 0.9s; }   /* scroll indicator */

@keyframes heroFadeUp {
  to {
    opacity: 1;
    transform: translateY(0);
  }
}
```

Zmiana vs obecny stan: obecne `fadeUp` uzywa ease (generic), nowy uzywa `cubic-bezier(0.16, 1, 0.3, 1)` (expo-out -- szybki start, lagodne wygaszenie, bardziej organic). Stagger jest precyzyjniejszy (6 slotow zamiast 4).

### 4.2 Scroll Reveal

Zostajemy przy IntersectionObserver (Layout.astro script), ale zmiana parametrow:

```js
// BEFORE
const observerOptions = { root: null, rootMargin: '0px', threshold: 0.1 };
// AFTER
const observerOptions = { root: null, rootMargin: '-60px 0px', threshold: 0.15 };
```

- `rootMargin: '-60px'` -- element musi wejsc 60px "w widok" zanim sie odpala, eliminuje glitch na samym edge
- `threshold: 0.15` -- 15% widocznosci wymagane (zamiast 10%), czucie bardziej intentional

Stagger dla list (skill cards, project cards):

```js
// W IntersectionObserver callback:
if (entry.target.dataset.staggerIndex) {
  const delay = parseInt(entry.target.dataset.staggerIndex) * 80; // 80ms miedzy elementami
  entry.target.style.transitionDelay = `${delay}ms`;
}
```

CSS zmiana: `duration-700` -> `duration-500` (700ms za wolne, 500ms sweet spot dla scroll reveal).

### 9.2 Focus States

```css
/* Global focus-visible */
:focus-visible {
  outline: 2px solid var(--color-primary);
  outline-offset: 3px;
  border-radius: 4px;
}

/* Remove default outline only when focus-visible handles it */
:focus:not(:focus-visible) {
  outline: none;
}

/* Buttons -- custom focus */
.btn:focus-visible {
  outline: 2px solid var(--color-primary-light);
  outline-offset: 3px;
  box-shadow: 0 0 0 4px rgba(212, 165, 71, 0.15);
}

/* Inputs -- focus jest juz zdefiniowany w input-field */
.input-field:focus-visible {
  border-color: var(--color-primary);
  box-shadow: 0 0 0 3px rgba(212, 165, 71, 0.1);
  outline: none; /* input ma wlasny focus indicator via border */
}

/* Cards -- interactive cards need focus */
.skill-card:focus-visible,
.project-card:focus-visible,
.pricing-card:focus-visible {
  outline: 2px solid var(--color-primary);
  outline-offset: 2px;
}
```
